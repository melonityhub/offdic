# مرحلهٔ دوم: AI، دوربین، ترجمه، ویجت و رابط

**به‌روزرسانی:** اکنون تنظیمات API مستقیم و Wrapper اضافه شده و بیلد/lint/emulator در CI موفق شده‌اند. گزارش جاری در `BUILD_VERIFICATION_FA.md` و راهنمای API در `AI_SETTINGS_FA.md` است. محدودیت‌های قابلیت‌ها در متن زیر همچنان معتبرند.

## رفع باگ صفحهٔ واژه و پیش‌نمایش ترجمه (۲۰۲۶-۱۰-۰۷)

- باز کردن واژه دیگر خطای «Webpage not available» با `net::ERR_HTTP_RESPONSE_CODE_FAILURE` نمی‌دهد؛ علت و جزئیات رفع در `RESULT_PAGE_FA.md`.
- صفحهٔ نتیجه خودکفاست: CSS، فونت‌های IRANSansX و آیکن‌ها به‌صورت `data:` درون صفحه می‌آیند و سند با `loadDataWithBaseURL(null, …)` مانند اپ اصلی بارگذاری می‌شود.
- هر ردیف فهرست جستجو، علاقه‌مندی‌ها، تاریخچه و دسته‌بندی‌ها پیش‌نمایش ترجمهٔ همان واژه را نشان می‌دهد.
- در صورت شکست WebView (خطای صفحه اصلی یا از دست رفتن render process)، معنی واژه در نمایش سادهٔ بومی با دکمهٔ تلاش دوباره نشان داده می‌شود.

## چیزی که اضافه شد

### دوربین و OCR

از «دوربین / ترجمه» یا «بیشتر ← ترجمهٔ متن / دوربین / OCR» وارد شوید.

- عکس‌گیری با برنامهٔ دوربین دستگاه، با URI امن FileProvider و تصویر کامل؛ نه thumbnail.
- انتخاب تصویر از Storage Access Framework؛ بدون دسترسی عمومی به حافظه.
- تشخیص متن با مدل **لاتینِ bundled ML Kit**؛ تصویر به سرور ما یا AI ارسال نمی‌شود.
- اصلاح ۸ حالت EXIF و downsample به حداکثر بُعد ۲۰۴۸ برای کاهش خطر OutOfMemory.
- پیش‌نمایش تصویر، کادر بلوک‌های متن، انتخاب بلوک با لمس، pan و pinch zoom.
- متن استخراج‌شده قابل ویرایش، کپی، جستجوی فرهنگ و ترجمه است.
- فایل موقت دوربین پس از پردازش پاک می‌شود؛ فایل‌های رهاشدهٔ قدیمی نیز پاکسازی می‌شوند.

**OCR فارسی پشتیبانی نمی‌شود.** مدل لاتین این قابلیت را ندارد؛ متن فارسی را می‌توان دستی وارد و ترجمه کرد. در سورس اصلی نیز مسیر OCR با ML Kit بررسی شد؛ مدل OCR خط فارسی یا API مجاز آن در این مخزن تأمین نشده است.

### ترجمهٔ متن

- ML Kit Translation، انگلیسی ↔ فارسی.
- دانلود رسمی مدل در اولین استفاده؛ پس از دانلود، ترجمه روی دستگاه انجام می‌شود.
- گزینهٔ Wi-Fi-only برای دانلود، جهت ترجمه، نتیجهٔ قابل انتخاب/کپی و پیام خطا.
- لغو نتیجهٔ درخواست، timeout و بستن translator؛ با خروج از صفحه نتایج کهنه نمایش داده نمی‌شوند.
- لغو انتظار لزوماً دانلود مشترکِ مدل در خود SDK را متوقف نمی‌کند.
- بدون قفل اشتراک داخل اپ. کیفیت ترجمه و دسترسی به سرور دانلود Google باید روی دستگاه هدف آزمایش شود.

این پیاده‌سازی از API رسمی استفاده می‌کند و ZIP مدل را داخل مسیرهای خصوصی و نسخه‌وابستهٔ ML Kit تزریق نمی‌کند. اولین نصب بدون اینترنت و بدون مدل از قبل دانلودشده، ترجمهٔ آفلاین ندارد.

### AI

تب AI یک فرم واقعی برای ارسال درخواست است، نه پاسخ از پیش‌نوشته‌شده. با این حال **مدل AI داخلی در APK وجود ندارد**. سورس اصلی AI را از صفحهٔ وب سرور و session کاربر بارگذاری می‌کند؛ نمی‌توان آن سرویس را فقط با حذف پرداخت مستقل کرد.

دو بخش اضافه شده:

- کلاینت Kotlin با HTTPS، timeout، لغو، محدودیت اندازهٔ پاسخ، رد redirect و تأیید کاربر قبل از ارسال متن.
- `gateway/server.py` برای اتصال به یک سرویس سازگار با OpenAI Chat Completions، شامل مدل محلیِ اجراشده روی سرور مانند ارائه‌دهندهٔ سازگار خودمیزبان.

در تب AI، «تنظیم نشانی سرویس AI» را باز کنید و **نشانی HTTPS gateway خودتان** را وارد کنید. توکن gateway اختیاری است، با Android Keystore رمز می‌شود و در URL، لاگ یا APK قرار نمی‌گیرد. کلید ارائه‌دهنده فقط روی سرور نگه داشته می‌شود.

قرارداد:

```http
POST /ai
Content-Type: application/json
Authorization: Bearer <gateway-token>

{"prompt":"متن کاربر"}
```

```json
{"answer":"پاسخ واقعی مدل"}
```

#### راه‌اندازی gateway

Python 3.10+؛ بدون وابستگی pip. متغیرهای محیطی روی **سرور خودتان**:

| متغیر | کاربرد |
|---|---|
| `AI_GATEWAY_TOKEN` | توکن طولانی و تصادفی برای محدودکردن دسترسی کلاینت‌ها |
| `AI_UPSTREAM_URL` | URL کامل `chat/completions` ارائه‌دهنده؛ HTTPS یا loopback HTTP برای مدل محلی |
| `AI_MODEL` | نام مدل موجود روی ارائه‌دهنده |
| `AI_UPSTREAM_KEY` | فقط اگر ارائه‌دهنده نیاز دارد؛ کلید روی سرور، نه اندروید |
| `PORT` | پیش‌فرض ۸۰۸۰، فقط loopback |

```sh
python3 gateway/server.py
```

سرور پشت reverse proxy با HTTPS، محدودیت نرخ درخواست، سقف تعداد اتصال هم‌زمان، محدودیت بدنه و دسترسی مناسب مستقر شود. سرور استاندارد Python به‌تنهایی لایهٔ انتشار عمومی محسوب نمی‌شود. `127.0.0.1` داخل گوشی به سرور شما اشاره نمی‌کند؛ در اپ دامنهٔ HTTPS واقعی را وارد کنید.

Gateway درخواست فاقد توکن معتبر را پیش از تماس با مدل رد می‌کند. prompt، کلید و خطای داخلی ارائه‌دهنده را لاگ/برنمی‌گرداند. پاسخ upstream در تست محلی mock شده است؛ **استنتاج واقعی مدل در این محیط آزمایش نشده**.

برنامه اشتراک نمی‌فروشد، اما ارائه‌دهندهٔ خارجی ممکن است هزینه داشته باشد. برای پرهیز از هزینهٔ API می‌توانید مدل و سرور خود را میزبانی کنید؛ منابع سخت‌افزاری همچنان لازم است.

### واژهٔ روز و ویجت

- کارت واژهٔ روز در خانه و ویجت قابل resize با رنگ‌بندی نزدیک به ویجت اصلی.
- انتخاب قطعی روزانه از **واژه‌های دارای معنی در دیتابیس محلی**؛ انتخاب خانه و ویجت یکسان است.
- Worker مستقل برای آماده‌سازی داده و به‌روزرسانی؛ هیچ IO دیتابیس روی thread گیرندهٔ broadcast انجام نمی‌شود.
- لمس ویجت متن واژه را در برنامه باز می‌کند؛ PendingIntent immutable است.
- refresh بعد از import دیتابیس؛ کار دوره‌ای پس از حذف آخرین ویجت لغو می‌شود.
- زمان اجرای به‌روزرسانی را Android تعیین می‌کند؛ به‌روزرسانی دقیق سر نیمه‌شب تضمین نمی‌شود.

این واژهٔ روز محلی است، **نه آرشیو تحریریهٔ سرور اپ اصلی**. از long-press صفحهٔ اصلی گوشی → Widgets → Offdic ویجت را اضافه کنید.

### بازسازی رابط

- نوار پایین دوباره ۵ بخش جستجو، AI، علاقه‌ها، پروفایل و بیشتر دارد؛ تاریخچه به بخش علاقه‌ها منتقل شد.
- آیکن‌های اصلی با densityهای موجود و state علاقه‌مندی منتقل شدند.
- نتایج در WebView محلی با CSS اصلی `style-results.css` و فونت‌ها/تصاویر وابسته رندر می‌شوند.
- همهٔ داده‌ها escape می‌شوند؛ JavaScript، file/content access، درخواست‌های شبکه و ناوبری خارجی نتیجه بسته‌اند.
- نشانی‌های دارایی در `style-results.css` هنگام ساخت صفحه به `data:` درون‌خطی تبدیل می‌شوند (`ResultAssets`)، پس سند به هیچ میزبان یا پاسخ ساختگی وابسته نیست. یک SVG صوتی که در CSS مرجع بود ولی فایلش در مخزن نبود، با آیکن سادهٔ محلی جایگزین شد.
- پروفایل فعلی فقط نام محلی است، نه حساب ابری اصلی.

**این بازسازی هنوز تطابق pixel-perfect نیست.** HTML و تعاملات اصلی به‌طور کامل پورت نشده‌اند؛ ابرواژه‌ها، انیمیشن‌ها، صفحه‌های ورود، تمام modalها و رابط دقیق دوربین تفاوت دارند. استفاده از CSS اصلی به‌تنهایی اثبات تطابق صددرصدی نیست.

## نتیجهٔ دابل‌چک این مرحله

- ۱۰ تست قرارداد داده/منابع/manifest/WebView و یک تست خروجی مستقل پاس شدند.
- ۵ تست HTTP gateway پاس شدند؛ پاسخ upstream در آن‌ها mock است.
- تست دستگاه برای OCR واقعی روی bitmap، زبان‌های ترجمه، HTML injection، endpoint و تست‌های قبلی نوشته شد.
- CI روی emulator API 35 اجرا شد و موفق بود؛ بیلد اصلی، lint و بیلد مستقل نیز پاس شدند.
- ابزار محلی Android SDK در دسترس نیست؛ بیلد و تست Android روی GitHub runner واقعی انجام شده‌اند، نه در محیط محلی.

با وجود بیلد و تست emulator موفق، خروجی «بدون باگ» یا «همسان صددرصدی» تضمین نمی‌شود؛ تست دستگاه فیزیکی، API واقعی و مقایسهٔ تصویری لازم است.
