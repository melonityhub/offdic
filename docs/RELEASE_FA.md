# ریلیز خودکار APK با گیت‌هاب اکشنز

تاریخ: ۲۰۲۶-۱۰-۰۷

هدف: هیچ بیلد دستی لازم نباشد. با هر مرج به `main`، خود گیت‌هاب نسخه می‌سازد، APK‌ها را بیلد می‌کند و Release منتشر می‌کند و نسخهٔ arm64 هم برای آپلود در گوگل درایو آماده می‌شود.

## تریگر و شمارهٔ نسخه

- **تریگر اصلی:** `push` روی `main` (یعنی هر مرج) + `workflow_dispatch` برای اجرای دوباره یا نسخهٔ دستی.
- **نسخهٔ خودکار:** `1.0.<شمارهٔ اجرا>` (`github.run_number`) و `versionCode = 1000000 + run_number`. هر اجرا یک شماره بیشتر می‌گیرد، پس کد نسخه روی دستگاه همیشه صعودی است.
- **تگ:** همان `<version>v` ساخته می‌شود و Release روی آن تگ بسته می‌شود (`v1.0.1`، `v1.0.2`، …).
- **نسخهٔ دستی:** در تب Actions → Release APK → Run workflow می‌توانید در فیلد `version` مثلاً `1.0.7` بنویسید؛ اگر تگ آن از قبل وجود داشته باشد، اجرا با خطای واضح متوقف می‌شود.
- بیلد محلی (`./gradlew :app:assembleDebug`) بدون هیچ پراپرتی، همان نسخهٔ پیش‌فرض `0.1.0` (کد ۱) را می‌سازد.

## چه چیزی منتشر می‌شود

| فایل | توضیح |
| --- | --- |
| `offdic-<version>-arm64-v8a.apk` | برای گوشی‌های امروزی (همین یکی به گوگل درایو می‌رود) |
| `offdic-<version>-armeabi-v7a.apk` | گوشی‌های قدیمی‌تر ۳۲ بیتی |
| `offdic-<version>-x86_64.apk` | شبیه‌سازهای اندروید |
| `offdic-<version>-universal.apk` | یک فایل برای همهٔ معماری‌ها (بزرگ‌تر) |
| `SHA256SUMS-<version>.txt` | هش همهٔ APKها برای بررسی سالم‌بودن دانلود |
| `offdic-standalone.zip` | سورس کامل و مستقل (بدون تاریخچهٔ گیت) |

- APKها **debug-signed** هستند: بدون هیچ تنظیم مخزنی نصب‌شدنی‌اند، ولی برای Google Play یا به‌عنوان کلید بلندمدت آپدیت مناسب نیستند.
- تقسیم‌بندی ABI فقط در ورک‌فلوی ریلیز فعال می‌شود (`-PabiSplits=true`) تا بیلد و تست‌های روزمره (debug) دست‌نخورده بمانند.
- پیش از انتشار، نسخهٔ داخل APK با `aapt2 dump badging` بررسی می‌شود که با ورودی ریلیز یکی باشد.

## پیاده‌سازی امضای ریلیز واقعی (اختیاری، بعداً)

اگر خواستید APK با کلید اختصاصی خودتان امضا شود، فقط این چهار مورد را در Settings → Secrets and variables → Actions به‌عنوان Repository secret اضافه کنید و دوباره ریلیز بگیرید؛ هیچ تغییری در کد لازم نیست:

| Secret | مقدار |
| --- | --- |
| `OFFDIC_KEYSTORE_FILE` | مسیر فایل keystore روی رانر (مثلاً `$RUNNER_TEMP/offdic.jks`؛ ورک‌فلو فعلی آن را از secret نمی‌سازد) |
| `OFFDIC_KEYSTORE_PASSWORD` | رمز keystore |
| `OFFDIC_KEY_ALIAS` | نام کلید |
| `OFFDIC_KEY_PASSWORD` | رمز کلید |

`app/build.gradle.kts` همین متغیرهای محیطی را می‌خواند و اگر موجود باشند از کلید واقعی استفاده می‌کند؛ در غیر این صورت به کلید debug برمی‌گردد.

## گوگل درایو

- ورک‌فلو بعد از هر ریلیز، فقط APK نسخهٔ arm64 (به‌همراه `SHA256SUMS` و `RELEASE.txt`) را روی برنچ اُرفن `drive-artifacts` می‌گذارد و هر بار آن را **جایگزین** (force-push) می‌کند؛ بنابراین تاریخچهٔ گیت رشد نمی‌کند و فقط آخرین نسخه آنجاست.
- این برنچ یک **مسیر انتقال** است، نه کانال توزیع: ابزارهای داخل sandbox نمی‌توانند assetهای GitHub را دانلود کنند، ولی `git fetch` کار می‌کند؛ پس دستیار همین فایل را برمی‌دارد و با کانکتور گوگل درایو در پوشهٔ «Offdic» می‌گذارد.
- برنچ `drive-artifacts` در تریگر ورک‌فلوی بررسی‌ها نادیده گرفته شده (`branches-ignore`) تا دقیقهٔ CI هدر نرود.
- اگر بعداً آپلود خودکار داخل Actions را ترجیح دادید (rclone + توکن حساب گوگل خودتان)، همین مرحله را حذف کنید؛ توضیح کامل در گفت‌وگوی همین PR آمده است.
- برای حذف برنچ واسط: `git push origin --delete drive-artifacts`.

## اجرای دستی همان بیلد روی سیستم خودتان

```bash
./gradlew :app:assembleRelease -PappVersionName=1.0.5 -PappVersionCode=1000005 -PabiSplits=true
# خروجی‌ها: app/build/outputs/apk/release/app-<abi>-release.apk
```

## آزمون‌ها

- `tools/test_contract.py::test_release_pipeline_builds_and_publishes_split_apks` قرارداد ورک‌فلو را قفل می‌کند: تریگر `main`، `contents: write`، چهار ABI، `sha256sum`، `gh release create`، خروجی ZIP مستقل، وجود برنچ واسط و نادیده‌گرفتنش در ورک‌فلوی بررسی‌ها، و پراپرتی‌های نسخه در `app/build.gradle.kts`.
- ورک‌فلوی بررسی‌ها (`android.yml`) دست‌نخورده کار می‌کند: بیلد debug، lint، export مستقل و تست دستگاه.
