# گزارش بررسی و اعتبارسنجی

تاریخ: ۲۰۲۶-۱۰-۰۶

**این گزارش مربوط به مرحلهٔ اول است.** گزارش جاری مرحلهٔ دوم در [FEATURES_FA.md](FEATURES_FA.md) آمده است: اکنون WebView امن، اینترنت برای دانلود مدل/AI، OCR، ترجمه و ویجت اضافه شده و ۱۴ تست میزبان پاس شده‌اند. موارد زیر سابقهٔ بررسی‌اند، نه توصیف کامل وضعیت فعلی.

## ماهیت ورودی

مخزن اولیه Gradle، Wrapper، تنظیمات ماژول و سورس Kotlin اصلی نداشت. Java حاصل دیکامپایل شامل متدهای تکراری ناشی از getter/component و خطاهای بازیابی کد است؛ کامپایل مستقیم آن قابل اتکا نیست. برای نمونه `models/database/PosModel.java` تعریف‌های getter تکراری دارد. ۷ فایل دارای نشانگر `Method not decompiled` هستند (بعضی چند متد)، از جمله `MainViewModel` و `CategoriesViewModel`؛ مسیر و شمارهٔ خطوط در موجودی ثبت شده‌اند.

پیمایش ماشینی تمام سورس و منابع انجام شد؛ **مرور دستی و تأیید هم‌ارزی تک‌تک متدهای ۱۴۹۳ فایل انجام نشده است**. بخش‌های اصلی بررسی دستی: manifest/navigation، home/search، result/FDHtml، POS، تم و فونت‌ها، ساختار دیتابیس، FDOfflineTranslator و مرزهای حساب/تبلیغ/پرداخت.

## تصمیم‌های این مرحله

- پروژهٔ جدید با namespace مستقل؛ نه تغییر APK اصلی و نه کامپایل SDKهای دیکامپایل‌شده.
- هیچ اتصال به بک‌اند اصلی، کلید داخلی، تحلیل‌گر یا SDK تبلیغ/پرداخت منتقل نشده است.
- دیتابیس فقط‌خواندنی با SQLite سیستم؛ وارد کردن فقط فایل معمولیِ قابل خواندن.
- دادهٔ کاربر در SQLite مستقل تا تعویض فرهنگ، علاقه‌مندی/تاریخچه را پاک نکند.
- انجام IO در executor سریال؛ باطل کردن نتایج کهنهٔ جستجو با generation و debounce.
- بستن cursorها/connectionها؛ خاموش کردن TTS و executor در پایان Activity.
- import روی فایل موقت، بررسی ساختار و سلامت پیش از جایگزینی.
- ورودی جستجو پارامتری است و `%`، `_` و backslash escape می‌شوند.
- HTML دیتابیس با TextView رندر می‌شود و JavaScript اجرا نمی‌کند. این انتخاب امن‌تر اما **از نظر ظاهر و رفتار معادل WebView اصلی نیست**.

## تست‌های اجراشده

دستور: `python3 tools/test_contract.py`

| آزمون | نتیجه |
|---|---|
| quick_check، foreign_key_check و ۱۸ جدول نمونه | پاس |
| EXPLAIN کوئری‌های SELECT قابل استخراج از خود فایل Kotlin برای دو زبان/لهجه | پاس |
| LIKE escaping، ورودی شبیه SQL injection، صفحه‌بندی و اولویت تطابق دقیق | پاس |
| مقایسهٔ ۳۴ کد POS انگلیسی، ۳۱ کد فارسی و ۳۴ معادل فارسی با سورس اصلی | پاس |

`git diff --check` نیز بدون خطا بود. این آزمون‌ها فقط قرارداد داده/منابع را بررسی می‌کنند و صحت کامپایل یا UX را ثابت نمی‌کنند. در نمونه ۲۴ ایندکس دیده شد؛ کارایی فایل کامل هنوز سنجیده نشده است.

## آزمون‌های نوشته‌شده ولی اجرا نشده

`app/src/androidTest/java/org/offdic/DictionaryTest.kt`:

- جستجو و خواندن جزئیات دو زبان، دسته‌بندی‌ها.
- حفظ دیتابیس پس از رد فایل نامعتبر.
- علاقه‌مندی و پاک کردن تاریخچه بدون حذف علاقه‌مندی.
- escaping و صفحات بدون هم‌پوشانی.
- تفاوت کدهای POS بین فارسی و انگلیسی.

CI برای assembleDebug، کامپایل APK تست و lint تعریف شده، اما اجرای آن تأیید نشده است. CI فعلی emulator راه نمی‌اندازد؛ تست‌های دستگاه باید جدا اجرا شوند.

## مانع اجرای اندروید در محیط فعلی

Java، Gradle و Android SDK در محیط نصب نبودند. تلاش اتصال به `services.gradle.org` و `raw.githubusercontent.com` با `SSL_ERROR_SYSCALL` ناموفق شد. بنابراین:

- APK تولید نشده است.
- Kotlin/منابع توسط کامپایلر Android تأیید نشده‌اند.
- Gradle Wrapper استاندارد دانلود/تولید نشده است.
- lint و instrumentation و مقایسهٔ تصویری اجرا نشده‌اند.
- هیچ ادعایی مبنی بر «بدون باگ» یا «بیلد موفق» وجود ندارد.

## ریسک‌ها و ادامهٔ ضروری

۱. ابتدا پروژه روی محیط مجهز بیلد شود و خطاهای احتمالی کامپایل/lint برطرف شود.
۲. import واقعی دیتابیس کامل، فضای ناکافی، قطع برنامه، rotation و هم‌زمانی چند Activity آزمایش شود. import فعلی WorkManager/foreground service ندارد؛ برای فایل‌های بسیار بزرگ باید فرایند مستقل و پیشرفت/لغو اضافه شود.
۳. لیست‌ها فعلاً ScrollView/LinearLayout هستند، نه RecyclerView؛ در پیمایش بلند مصرف حافظه باید اصلاح شود. علاقه‌ها/تاریخچه فعلاً ۱۰۰۰ مورد نمایش می‌دهند.
۴. فایل کامل برای ارزیابی canonical، ایندکس‌ها، کارایی و روابط خانوادهٔ واژه لازم است.
۵. برای تطابق کامل، XML/CSS/JS، navigation و قابلیت‌های باقی‌ماندهٔ چک‌لیست بازسازی شوند؛ جایگزین‌های TTS/تشخیص گفتار معادل مکانیسم اصلی نیستند.
۶. برای AI، حساب و sync باید بک‌اند مجاز/مستقل و قرارداد سرویس مشخص شود؛ این بخش‌ها با حذف خرید قابل تأمین نیستند.
۷. برای تأیید بصری، نسخهٔ قابل اجرای اصلی یا screenshotهای مرجع از تمام حالت‌ها لازم است؛ اکنون مقایسهٔ pixel-level انجام نشده.
۸. متن مجوز IRANSansX موجود در assets حفظ شده، اما مجوز استفادهٔ مستقل فونت‌ها و سایر منابع باید پیش از انتشار بررسی شود.
